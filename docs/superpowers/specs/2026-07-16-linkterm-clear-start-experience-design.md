# LinkTerm 清晰启动体验设计规格

> 版本：2026-07-16（用户确认的工作区边界修订版）

## 目标

让用户第一次进入 LinkTerm 时，立即理解两件事：

1. 打开之前保存的设备工作区；
2. 创建或配置一个新的设备工作区。

同时支持另一种常见场景：用户只想临时打开一个串口终端，而不想先填写完整的设备、调试器和固件信息。

核心模型不是“多个打开入口”，而是：

> 选择一个已保存的设备工作区，或创建一个临时/持久的连接；打开终端后，人和 AI 在同一个会话中观察和操作。

## 领域边界

LinkTerm 的配置分为三层，首页和 UI 必须按这三层组织。

### 系统配置

系统级配置对所有工作区生效，包括：

- MCP 注入和 MCP server 设置；
- Agent 配置、Agent 行为和全局 AI 设置；
- 全局审计、活动观察和应用偏好。

系统配置不属于某一台设备，不出现在工作区卡片的设备摘要中，也不因为切换工作区而复制或覆盖。

### 设备工作区

工作区描述“这是什么设备，以及怎样连接和使用它”，包括：

- 工作区名称和设备身份；
- 串口、J-Link、RTT 等连接方式及参数；
- 固件文件和烧录/调试相关事实配置；
- 与该设备相关的非敏感诊断参数。

工作区可以保存并在首页重复打开。工作区不保存 MCP 或 Agent 全局配置。

### 运行会话

会话是一次实际打开的终端运行实例，使用现有 SessionManager、WriteQueue、Transport 和终端输入边界。

- 已保存工作区可以启动会话；
- 仅串口也可以先创建临时会话，不保存为工作区；
- 临时会话可以在用户明确选择后保存为轻量工作区；
- 人工输入和 AI 输入始终进入同一个会话，不互斥、不抢占焦点。

## 首页信息架构

首页只有两个主要区域，顺序固定。

### 1. 已保存的工作区

该区域优先级最高，打开 App 后首先显示。

每张卡片显示：

- 工作区名称；
- 设备摘要；
- 已配置的连接方式，例如“串口”“串口 + J-Link”“RTT”；
- 固件摘要（如果有）；
- 最近使用时间或状态。

每张卡片的主要动作只有“打开”。编辑、复制和删除是次级操作，不与打开动作竞争。

工作区类型使用清晰标签：

- `完整设备工作区`：含设备连接、调试/烧录或 RTT 等高级信息；
- `仅串口工作区`：只保存串口连接参数。

没有已保存工作区时，显示空状态，但不显示当前 COM 端口列表，也不把 J-Link、RTT 或 readiness 清单放在主区域。

### 2. 控制配置（用户可见名称建议为“新建设备工作区”）

该区域是创建新设备工作区的唯一入口。点击后进入现有配置流程，第一步选择配置范围：

- `仅串口连接`：发现端口、填写波特率并打开终端；用户可以选择“仅本次使用”或“保存为仅串口工作区”；
- `完整设备工作区`：配置设备身份、串口/J-Link/RTT、固件等设备级信息并保存。

串口发现只在该流程的连接对话框中出现。首页不显示 COM 列表，不再提供独立的“手动串口”“打开串口”“观察设备输出”并列卡片。

“控制配置”仍可作为内部组件和开发者术语保留，但用户看到的入口应表达实际任务，例如“新建设备工作区”或“配置设备工作区”。

## 系统级 MCP/Agent 入口

MCP 注入和 Agent 配置从设备工作区流程中移出，作为系统级设置：

- 通过顶栏或应用设置入口访问；
- 不要求用户创建工作区时重复填写；
- 不在首页与已保存工作区争夺主视觉；
- 切换工作区不会改变全局 MCP/Agent 设置，除非用户主动修改系统配置。

这不改变现有 MCP、Agent 或自动执行后端行为，只改变它们在首页的信息架构和归属说明。

## 高级设备与首次成功

- J-Link、RTT、固件和详细诊断作为完整工作区的可选高级字段，默认不抢占首页主流程；
- 首次成功向导不作为人工打开串口的主按钮，只在连接异常、配置缺失或用户主动查看时出现；
- Activity Center 默认关闭，只用于观察 AI 活动和审计；
- 不恢复批准、暂停、接管、恢复或互斥抢占机制；
- AI 活动不得禁用人工输入、抢占终端焦点或要求用户确认。

## 数据和兼容性要求

已有数据不得删除或静默丢失：

- 现有完整 `ControlProfileRecord` 映射为“完整设备工作区”；
- 现有 `SavedConnectionProfile` 中的串口记录映射为“仅串口工作区”或可从新建流程继续使用；
- MCP/Agent 现有全局配置保持原位置和语义；
- 旧数据无法完整映射时，显示缺失字段和修复入口，不自动覆盖用户配置。

## 组件边界

实现阶段以 GitNexus impact 结果为准，预计涉及：

- `src/renderer/features/readiness/StartCenter.tsx`：工作区列表、空状态、新建设备工作区入口和高级区域层级；
- `src/renderer/components/ControlProfilePanel.tsx`：仅串口/完整工作区的创建选择和保存语义；
- `src/renderer/components/ConnectionDialog.tsx`：在用户进入连接流程后显示串口发现和所有连接类型；
- `src/renderer/App.tsx`：无会话空状态布局、工作区打开后的会话工具显示；
- `src/renderer/components/AgentIntegrationsPanel.tsx`：保持系统级入口，不把 Agent 配置塞回工作区；
- `src/renderer/i18n/zh.ts`、`src/renderer/i18n/en.ts`：工作区类型、创建流程和系统配置文案；
- 对应 renderer 单元测试和集成测试。

不修改 SessionManager、WriteQueue、Transport、IJLinkBackend 或 MCP 工具执行策略，除非测试证明现有边界无法支撑上述 UI 语义。

## 交互与错误处理

- 已保存工作区打开失败时，错误显示在该卡片或打开结果区域，并提供编辑/修复入口；
- 仅串口模式中，端口为空、端口不存在或波特率无效时，错误显示在连接对话框字段附近；
- 创建完整工作区时缺少设备、连接或固件事实，只标记缺失字段，不伪造“就绪”；
- 高级设备检查失败不阻断仅串口会话；
- Activity Center、系统设置和诊断抽屉的开关不改变终端焦点；
- 中英文切换后，工作区、系统配置和会话三个概念的文案保持一致。

## 验收标准

### 首页与工作区

- 打开 App 后第一眼看到已保存工作区；
- 已保存工作区可以一键打开；
- 没有已保存工作区时，空状态仍明确显示“新建设备工作区”；
- 首页不展示当前 COM 列表，不出现重复的手动串口卡片；
- 工作区卡片不显示 MCP/Agent 配置字段。

### 新建与临时串口

- 用户点击新建设备工作区后，可以选择“仅串口连接”或“完整设备工作区”；
- 仅串口连接可以只使用一次，也可以保存为轻量工作区；
- 完整设备工作区可配置设备、连接方式和固件；
- 串口发现只在连接流程内显示。

### 系统级 AI 配置

- MCP 注入和 Agent 配置从系统级入口访问；
- 切换工作区不会重置或复制全局 MCP/Agent 配置；
- AI 自动操作不弹批准要求；
- AI 运行期间人工仍可点击终端并输入，双方输出在同一会话中。

### 质量与安全

- 中英文 UI 语义一致；
- 大窗口和小窗口均无明显重叠、截断或横向滚动；
- 相关 renderer 单测、集成测试、lint、TypeScript、build 和 license 检查通过；
- 每个修改 symbol 前有 GitNexus upstream impact 证据，完成后有 `detect_changes()` 证据；
- 不执行未经授权的烧录、擦除、复位或调试硬件副作用。

## 非目标

- 不把 MCP/Agent 配置复制到每个工作区；
- 不新增云服务、远程审批、数据库或默认遥测；
- 不恢复批准、暂停、Take Over、恢复或互斥抢占机制；
- 不把首页重排描述成整个 A+D 工程完成。
