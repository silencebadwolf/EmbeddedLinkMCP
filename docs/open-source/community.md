# 社区与贡献

本文合并社区协作、贡献、安全、支持和行为准则，作为公开仓库的主要协作入口。

## 开始之前

- Bug、兼容性问题和小型改进可以直接创建 Issue。
- 较大的功能、公共 API 变化、数据格式变化或架构调整，应先创建 Issue 说明目标、使用场景和备选方案，等待维护者确认方向。
- 安全漏洞不要创建公开 Issue，请按本文的私密报告流程处理。
- 不要提交密码、Token、私钥、设备序列号、客户数据、绝对个人路径或受限制的厂商文件。
- 闭源集成、私有化交付和商业支持请先阅读 [许可与商业授权](licensing.md)。

## 开发环境

需要 Node.js `^22.13.0 || >=24.0.0`、pnpm `9.15.0`，且不能混用 npm/yarn：

```bash
corepack enable
corepack prepare pnpm@9.15.0 --activate
pnpm install --frozen-lockfile
pnpm run ci:check
```

本地没有串口设备、SSH 服务或 J-Link 探针也应能运行绝大多数测试。涉及真实硬件的变更，请在 PR 中明确硬件型号、测试范围和无法自动化的验证项，但不要公开设备秘密或客户固件。

## 变更原则

- 保持改动聚焦，一个 PR 解决一个问题。
- 遵守 `AGENTS.md` 与现有模块边界；不要绕过 `SessionManager.write` / `WriteQueue` 写入 transport。
- 主进程、core、J-Link 与 MCP 代码使用相对 ESM import 并带 `.js` 后缀；`@/` 仅用于 renderer 和测试。
- 新增运行时依赖时，同步更新 `third-party-manifest.json` 和 `licenses/`，并运行 `pnpm run validate:licenses`。
- 为行为变更添加或更新测试；不要只更新生成产物。
- 不要提交 `dist/`、`release/`、覆盖率、日志、本地配置或 IDE 用户状态。

## Pull Request

提交信息使用 Conventional Commits，例如：

```text
fix: 处理 MCP 端口冲突
feat: 添加新的终端会话能力
docs: 完善开源贡献说明
```

PR 应包含：问题与目标、实现摘要、风险/兼容性说明、验证命令及结果、相关截图或日志（如适用）。提交 PR 即表示你已阅读并同意 [贡献者许可协议](licensing.md)；模板中必须勾选对应确认项。

维护者会按正确性、安全性、兼容性、可维护性、测试和许可证合规性审查。合并、版本计划和发布时间由维护者根据项目整体情况决定。

## 社区支持

使用问题、兼容性问题和功能建议请通过 [Gitee Issues](https://gitee.com/wake_micro/link-mcp/issues) 提交。提问前请先搜索已有 Issue，并提供：LinkTerm 版本/提交、操作系统、Node/pnpm 版本、复现步骤、预期与实际结果，以及经过脱敏的日志。

社区支持按维护者可用时间提供，不承诺响应时限。涉及串口、SSH、J-Link、目标芯片或厂商工具时，请说明设备与工具版本；不要附上授权文件、私钥、客户固件或未脱敏的绝对路径。

以下内容不适合公开 Issue：未修复安全漏洞、商业合同、许可证报价、客户数据和凭据。安全问题按下文私密报告流程处理；闭源集成与商业支持按 [许可与商业授权](licensing.md) 联系。

## 支持边界

项目不保证适配所有 J-Link 型号、目标芯片、USB/串口驱动、企业代理或定制固件。自动化测试通过不等于真实硬件、安装包签名或生产部署验收；发布说明会列出已验证范围。

## 安全策略

在首个稳定版本发布前，安全修复只保证进入 `main` 和最新预发布版本。稳定版发布后，默认仅维护最新稳定大版本；具体例外会在本文和 [治理、路线图与变更记录](project.md) 中说明。

未签名的开发构建、历史 `release/` 目录产物、本地修改版和第三方重新打包版本不属于官方安全支持范围。

## 私密报告漏洞

请不要为未修复漏洞创建公开 Issue，也不要附上真实凭据、客户固件、私钥或可直接攻击生产系统的数据。

1. 优先使用代码托管平台的私密漏洞报告功能（若仓库已启用）。
2. 若该功能不可用，请通过仓库所有者主页列出的非公开联系方式联系维护者，只先提供影响摘要和回联方式。
3. 维护者建立私密通道后，再提供复现步骤、受影响版本、平台、影响、最小 PoC 和建议缓解措施。

维护者会尽力在 7 天内确认收到，并在完成初步评估后协调修复与披露时间。该时间是目标而非服务等级承诺。项目当前不承诺漏洞赏金。

特别欢迎报告以下问题：本地 MCP HTTP 鉴权绕过、任意命令/代码执行、路径穿越、凭据或终端内容泄露、IPC 边界绕过、恶意工作区导致的代码执行、更新/安装包供应链风险，以及 J-Link/串口/SSH 操作越权。

仅说明依赖扫描器输出而没有可达性或影响分析的报告也会被查看，但可能降低优先级。对你自己的系统进行最小化测试；不要扫描或访问第三方设备和数据。

修复发布后会在变更记录和托管平台公告中说明受影响版本、升级路径和必要缓解措施。公开披露前会尽量为用户保留合理升级时间。

## 行为准则

LinkTerm 社区致力于提供友善、安全、专业且不骚扰任何人的协作环境，不因经验、身份、背景、语言、能力或观点差异而区别对待。

我们鼓励：

- 针对技术事实和可验证证据讨论，对人保持尊重；
- 接受善意反馈，清楚说明假设、风险和不确定性；
- 保护他人的隐私、凭据、客户数据与未公开漏洞；
- 在分歧中寻求可复现测试、项目约束和用户价值的共同基础；
- 发现错误后及时更正，并帮助新贡献者理解项目。

不可接受：

- 侮辱、威胁、骚扰、歧视、跟踪或公开他人隐私；
- 性化内容、不受欢迎的关注或人身攻击；
- 恶意破坏、刷屏、冒充、欺诈或蓄意提交秘密/恶意代码；
- 以公开漏洞、客户资料或凭据向他人施压；
- 在被要求停止后继续不当行为。

本准则适用于项目仓库、Issue、代码评审、讨论、线上线下活动，以及代表项目参与其他社区的场景。维护者可删除内容、限制互动、关闭 Issue/PR、暂时或永久禁止参与，并会尽量按行为的影响、持续时间和重复程度采取相称措施。

报告不当行为时，请优先通过托管平台提供的私密联系功能或仓库所有者主页列出的非公开联系方式联系维护者。不要在公开 Issue 中披露受害者身份、私人对话或其他敏感材料。维护者会尽可能保护报告者隐私，但无法承诺超出平台能力或法律要求的绝对保密。

如维护者本人涉及报告，应联系其他具有仓库管理权限的维护者；在项目建立独立申诉渠道前，无法妥善回避的案件可能需要平台方介入。
