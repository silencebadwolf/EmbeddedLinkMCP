# 治理、路线图与变更记录

本文合并项目治理、路线图和变更记录，作为维护者和贡献者判断项目方向的单一入口。

## 项目治理

LinkTerm 当前采用维护者主导的治理模式。维护者负责路线图、架构边界、合并、发布、安全响应、商标与双许可决策；贡献者通过 Issue、设计讨论、代码评审和 Pull Request 参与。

## 决策原则

1. 用户安全、凭据隔离和硬件操作边界优先；
2. 保持桌面 UI、MCP 自动化与真实运行时事实一致；
3. 优先兼容、可测试、可维护的渐进式变化；
4. 公共接口、持久格式和许可证变化需要公开记录；
5. 无法达成共识时，负责该领域的维护者作最终决定并记录理由。

## 角色

- **贡献者**：提交 Issue、文档、测试或代码，并遵守 [社区与贡献](community.md) 和 [贡献者许可协议](licensing.md)。
- **维护者**：持续审查贡献、管理 Issue、保护安全边界并维护发布质量。
- **发布负责人**：验证质量门禁、第三方许可证、产物来源、签名状态和发布说明后创建版本。

维护者身份以仓库托管平台的权限和公开维护者列表为准。长期稳定贡献者可由现有维护者邀请加入；权限可因长期不活跃、安全风险或违反行为准则而调整。

## 许可证与贡献

公共版本按 AGPL-3.0-or-later 发布。商业许可只覆盖项目维护者有权授权的材料。为维持双许可能力，代码和文档贡献必须接受 [CLA](licensing.md)；不接受 CLA 的建议仍可通过 Issue 讨论，但不会直接合并为受版权保护的贡献。

## 发布与安全

只有维护者指定的发布负责人可以声明“官方发布”。未签名的 CI/本地构建必须标为开发产物。安全事件按 [社区与贡献](community.md) 私密处理，必要时可在正常讨论流程之外优先修复。

## 路线图

本路线图表达当前方向，不是交付承诺。优先级会根据安全问题、真实硬件反馈、维护能力和贡献者需求调整。

### 开源发布准备（当前）

- 建立 AGPL-3.0-or-later + 商业许可证双许可与 CLA；
- 完善贡献、安全、支持、治理、Issue/PR 模板和变更记录；
- 清理机器专属配置、个人路径与历史发布产物；
- 关闭生产依赖高危漏洞，完善完整依赖/原生二进制归因；
- 明确官方仓库、更新源、版本和产品命名。

### 首个公开预发布版

- Windows 安装/卸载与基本 UI 冒烟测试；
- Windows 代码签名，macOS 签名与 notarization（取得相应凭据后）；
- 为每个平台生成校验和、SBOM 与第三方声明；
- 在真实串口、SSH、J-Link/RTT 工作流上记录验收矩阵；
- 发布已知限制、安全边界和升级/回滚说明。

### 后续方向

- 稳定 MCP 工具契约、兼容策略与扩展开发文档；
- 改进崩溃诊断、可观察性、隐私控制和安全更新；
- 在依赖方向清晰后，将共享 contracts 与可复用 runtime 逐步拆分；
- 扩展跨平台安装验证和更多真实硬件覆盖。

### [0.1.0] - 2026-08-07

#### Added

- AGPL-3.0-or-later 公共许可证与付费商业授权路径。
- 合并开源贡献、安全、支持、治理、路线图、CLA、商业授权和协作模板文档，减少根目录公开文档噪音。

#### Security

- 公开发布前将持续跟踪生产依赖审计、安装包签名和供应链材料。
